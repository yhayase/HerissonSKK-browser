# システム辞書の設定と検証

拡張機能のポップアップから「辞書設定を開く」を押すと設定画面が開きます。初期状態は同梱の基本辞書 S（JSON）です。初回準備中は構成を編集できません。

## 辞書を選ぶ

「追加する辞書」で基本 S・基本 L・人名・地名・郵便番号を選び、形式と取得元を別々に指定します。同梱 S はテキストと JSON を切り替えられます。公開カタログの郵便番号辞書はテキストのみです。取得元がない組み合わせは追加できません。

「上へ」「下へ」で基本辞書も含めて順序を変え、有効状態を選び、「構成を保存・必要な辞書を取得」で反映します。編集途中の内容は変換に使われません。別の設定画面の保存を検出すると編集中の内容を保持して競合を表示します。編集を破棄し、最新の構成からやり直してください。保存前の検出は行いますが、同時保存を防ぐ原子的な比較更新を UI の RPC は提供しません。

ローカルファイルは辞書名と形式を指定してインポートします。対象で既存辞書を選ぶと同じ辞書を再インポートできます。ファイル形式は拡張子から自動判定しません。空ファイルは扱えず、上限は 64 MiB です。ファイルは分割して転送します。同時に転送できるファイルは一つで、転送が 60 秒間進まない場合は中断します。JSON は `copyright`、`license`、`okuri_ari`、`okuri_nasi` を持つ公式形式を使用します。

## 候補と保存

システム辞書は上から順に候補を統合します。下位辞書だけにある候補も残ります。同じ単語・送り条件の候補はまとめ、最上位の注釈を表示します。「候補の確認」では出典ごとの注釈と送り条件を確認できます。「送り仮名の全条件を確認」と、特定の送り仮名を指定する検索は結果が異なります。

実際の変換では学習した候補をシステム辞書より先に表示します。先頭以外の候補を選んで確定すると学習されます。システム辞書の順序を変えても、学習順が優先されるため見かけの先頭候補が変わらない場合があります。

構成は同じブラウザープロファイル内の全タブで共有します。変更中の変換候補一覧は保持し、次の変換から新構成を参照します。ブラウザーやプロファイルをまたぐ同期ではありません。

辞書を無効化しても保存済みの辞書データは削除しません。再有効化や同じプロファイルでの再起動後に利用できます。画面には取得元、保存サイズ、ハッシュ、インポート日時、取得元の更新日時、見出し数を表示します。取得前の値や取得元から提供されない日時は「不明」です。

外部辞書の初回取得・明示的な更新には `raw.githubusercontent.com` への通信権限とネットワークが必要です。変換する入力文字列をその取得先へ送信しません。取得済み辞書による変換はオフラインで動作します。取得・解析・保存が完了するまでは直前の構成で検索でき、失敗しても直前の構成を保持します。通信状態やファイルを直して再試行できます。

## 自動検証

`npm test` は Chrome、`npm run test:firefox` は Firefox のビルド、既存の入力欄・textarea・contenteditable・Monaco・登録学習テスト、共通の設定画面 E2E を実行します。共通ランナーは `test/system-dictionary-e2e.mjs` です。ブラウザーの実際の設定 DOM、インポート処理、打鍵、変換結果を検証します。Chrome のクリックとファイル指定はブラウザー自動操作を使用します。Firefox の BiDi は拡張機能ページのネイティブ入力を制限するため、設定画面では DOM の click/input/change と File/DataTransfer で選択を再現します。Firefox の OS ファイル選択ダイアログ自体は検証しません。両ブラウザーの通常ページでの変換は信頼されたキーボード操作で検証します。

初期化中の操作禁止は revision 0 の状態応答をテスト境界で再現し、実際の設定画面の操作可否と初期化後の復帰を検証します。Firefox は拡張機能ページへの preload が適用されないため、既存のポーリングを停止して実際のビルド済み設定エントリーポイントを再実行します。

外部辞書の取得待機・通信失敗・不正 JSON は、テスト中だけ Background の取得境界を置き換えて決定的に再現します。設定処理、解析、保存、候補合成は製品コードを使用します。その置き換えを解除してブラウザーを終了した後、同じプロファイルを外部接続不能のプロキシ設定で再起動し、保存済み候補の利用と実際の更新失敗を確認します。公開配信先の稼働確認や巨大ファイルの負荷試験を代替するものではありません。

Chrome の設定画面画像、Firefox の通常入力画面画像、実行ログとテスト用プロファイル・ファイルは追跡対象外の `.output/system-e2e-chrome/`、`.output/system-e2e-firefox/` に保存します。Firefox BiDi は拡張機能ページの画像取得も制限するため、設定画面は DOM と狭幅時の幅測定値を記録します。Firefox の既存画面画像も `.output/firefox-verify-screenshot.png` に保存します。Chrome はリポジトリー内のテスト用 Chrome、Firefox は `/snap/firefox/current/usr/lib/firefox/firefox` を既定で使用します。`CHROME_PATH`、`FIREFOX_PATH` で変更できます。Firefox の設定画面自動操作にはテスト起動時の `--remote-allow-system-access` を使用します。通常利用でこのフラグは不要です。
