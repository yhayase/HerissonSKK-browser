# システム辞書の設定と検証

拡張機能のポップアップから「辞書設定を開く」を押すと設定画面が開きます。初回起動時に公式配信先（raw.githubusercontent.com）から基本辞書 S（JSON）を自動取得します。初回はインターネット接続が必要です。取得中は構成を編集できません。失敗した場合は状態とエラーが表示され、設定画面の「初期化を再試行」でやり直せます。取得後は端末内のキャッシュを使用し、オフラインでも起動・変換できます。

旧版で同梱辞書を使っていた場合は、保存済みの辞書と有効・無効の設定を保持し、更新先だけを公式 URL へ移行します。空の構成や、独自辞書だけを使う構成には基本辞書を追加しません。

## 辞書を選ぶ

設定画面の一つの一覧で、辞書の追加、順序、形式、取得元、有効状態を編集します。「カタログから追加」では基本辞書 S・M・L、人名、地名、郵便番号を選び、形式と取得元を別々に指定します。基本辞書 S と M はテキストまたは JSON を明示して追加できます。公開カタログの郵便番号辞書はテキストのみです。取得元がない組み合わせは追加できません。

「↑」「↓」で基本辞書も含めて順序を変え、有効状態を選び、「保存」で反映します。すべての行を「削除」で削除でき、空の構成も保存して再起動後まで維持できます。編集途中の内容は変換に使われません。別の設定画面の保存を検出すると編集中の内容を保持して競合を表示します。編集を破棄し、最新の構成からやり直してください。保存前の検出は行いますが、同時保存を防ぐ原子的な比較更新を UI の RPC は提供しません。同時に保存が始まった場合は後から公開された保存が優先されます。

任意の取得先を使う場合は「URLから追加」で辞書名、テキストまたは JSON の形式、`http://` または `https://` で始まる取得元 URL を明示します。一覧内の名前・形式・URLの入力は直ちに未保存の変更として保持し、「保存」で反映します。並べ替えでも入力内容とキーボードフォーカスを保持します。保存済みの同じURLから取り直す場合は「更新（即時）」を押します。ユーザー名やパスワードなどの認証情報を含む URL は受け付けません。

新規・取得元や形式を変更したカスタム辞書を保存するとき、明示的に更新するときは、そのホストだけへの任意アクセス許可をブラウザーに要求します。拒否しても構成と保存済み辞書は変わらず、同じ操作をもう一度実行して再試行できます。取得時は Cookie や HTTP 認証情報を送信しません。別 URL へのリダイレクトも受け付けません。辞書を無効化または構成から削除しても、取得済みキャッシュや付与済みの任意アクセス許可を自動削除しません。

ローカルファイルは辞書名と形式を指定してインポートします。対象で既存辞書を選ぶと同じ辞書を再インポートできます。ファイル形式は拡張子から自動判定しません。空ファイルは扱えず、上限は 64 MiB です。ファイルは分割して転送します。同時に転送できるファイルは一つで、転送が 60 秒間進まない場合は中断します。JSON は `copyright`、`license`、`okuri_ari`、`okuri_nasi` を持つ公式形式を使用します。

補足説明は「?」へのマウスオーバーまたはキーボードフォーカスで表示し、Escapeで閉じられます。更新とインポートは即時反映、それ以外の構成変更は保存時に反映します。

## 候補と保存

システム辞書は上から順に候補を統合します。下位辞書だけにある候補も残ります。同じ単語・送り条件の候補はまとめ、最上位の注釈を表示します。設定画面下部の「候補診断」から、読み取り専用の候補診断画面を開けます。この画面には保存済みで現在使用中の構成だけを反映し、システム辞書の候補順と、候補ごとの出典、注釈、送り条件を表示します。「送り仮名の全条件を確認」と、特定の送り仮名を指定する検索は結果が異なります。

実際の変換では学習した候補をシステム辞書より先に表示します。先頭以外の候補を選んで確定すると学習されます。システム辞書の順序を変えても、学習順が優先されるため見かけの先頭候補が変わらない場合があります。

構成は同じブラウザープロファイル内の全タブで共有します。変更中の変換候補一覧は保持し、次の変換から新構成を参照します。ブラウザーやプロファイルをまたぐ同期ではありません。

辞書を無効化しても保存済みの辞書データは削除しません。再有効化や同じプロファイルでの再起動後に利用できます。各行の「詳細」を開くと、取得元、保存サイズ、ハッシュ、インポート日時、取得元の更新日時、見出し数を確認できます。取得前の値や取得元から提供されない日時は「不明」です。

公開カタログの外部辞書の初回取得・明示的な更新には `raw.githubusercontent.com` への通信権限とネットワークが必要です。カスタム辞書には前述の取得先ごとの任意アクセス許可が必要です。変換する入力文字列を取得先へ送信しません。取得済み辞書による変換はオフラインで動作します。取得・解析・保存が完了するまでは直前の構成で検索でき、失敗しても直前の構成を保持します。通信状態やファイルを直して再試行できます。

## 自動検証

`npm test` は Chrome、`npm run test:firefox` は Firefox のビルド、既存の入力欄・textarea・contenteditable・Monaco・登録学習テスト、共通の設定画面と候補診断画面の E2E を実行します。共通ランナーは `test/system-dictionary-e2e.mjs` です。ブラウザーの実際の設定 DOM、別ページの候補診断 DOM、インポート処理、打鍵、変換結果を検証します。Chrome のクリックとファイル指定はブラウザー自動操作を使用します。Firefox の BiDi は拡張機能ページのネイティブ入力と画像取得を制限するため、既存の生の BiDi ナビゲーションを使い、設定画面と候補診断画面を実 DOM で検証します。設定画面では DOM の click/input/change と File/DataTransfer で選択を再現します。Firefox の OS ファイル選択ダイアログ自体は検証しません。両ブラウザーの通常ページでの変換は信頼されたキーボード操作で検証します。

初期化中の操作禁止は revision 0 の状態応答をテスト境界で再現し、実際の設定画面の操作可否と初期化後の復帰を検証します。Firefox は拡張機能ページへの preload が適用されないため、既存のポーリングを停止して実際のビルド済み設定エントリーポイントを再実行します。

外部辞書の取得待機・通信失敗・不正 JSON は、テスト中だけ Background の取得境界を置き換えて決定的に再現します。設定処理、解析、保存、候補合成は製品コードを使用します。その置き換えを解除してブラウザーを終了した後、同じプロファイルを外部接続不能のプロキシ設定で再起動し、保存済み候補の利用と実際の更新失敗を確認します。公開配信先の稼働確認や巨大ファイルの負荷試験を代替するものではありません。

任意アクセス許可のネイティブ確認ダイアログは E2E で自動操作しません。テストでは `permissions.request` の許可・拒否応答を置き換え、ローカル取得先のオリジンをビルド済み manifest に実行中だけ付与し、終了時に元へ戻します。HTTP 取得、Cookie・認証情報を送らない要求、解析、IndexedDB への保存は製品コードを通します。アクセス許可の確認中に別画面で構成が変わる競合は、保留した許可応答を使うユニットテストで検証します。ブラウザー上で同時に許可操作を進める競合の再現ではありません。

Chrome の設定画面と候補診断画面の画像、Firefox の通常入力画面画像、実行ログとテスト用プロファイル・ファイルは追跡対象外の `.output/system-e2e-chrome/`、`.output/system-e2e-firefox/` に保存します。Firefox の設定画面と候補診断画面は DOM の証跡を、設定画面は狭幅時の幅測定値も記録します。Firefox の既存画面画像も `.output/firefox-verify-screenshot.png` に保存します。Chrome はリポジトリー内のテスト用 Chrome、Firefox は `/snap/firefox/current/usr/lib/firefox/firefox` を既定で使用します。`CHROME_PATH`、`FIREFOX_PATH` で変更できます。Firefox の設定画面自動操作にはテスト起動時の `--remote-allow-system-access` を使用します。通常利用でこのフラグは不要です。
